<Callout title="Poppy 1.0">
`@adonis-agora/authkit-poppy` implements [Poppy 1.0](https://personalagentprotocol.org/docs/1.0/spec). By default it serves version `1.0`;
[`versions`](#serving-several-versions) adds more. The package version follows the spec version: `1.x` implements Poppy `1.x`.
`@adonis-agora/authkit-server` only provides the
[extension points](/docs/authkit/personal-agents#other-protocols-extensions) the package plugs into.
</Callout>

Poppy lets a **personal agent** (an AI assistant acting for one user) work with your app: find
it, start a session for its user, have the user sign in and approve what the agent may do, call
your APIs and your company agent, and browse your website — all in one session. It runs **next to
[PACT](/docs/authkit/personal-agents)**: an app can serve both.

How it differs from PACT: **Sessions and account access are separate**. The agent identifies itself
by its `client_id` — an HTTPS URL serving its metadata document — and declares its Session on every
request with a `Poppy-Session` header: a JWT it signs for that one request with a short-lived
delegated key. A request with only that header is **signed out**. Account access is plain OAuth, so
your app runs an authorization server: a request that also carries an **access token** is signed in.
Sign-in, refresh and revocation don't know the Session, and one sign-in can serve several Sessions.

## How the user signs in

To act on the user's account, the user signs in to **your** app and approves scopes. The protocol
defines no scopes of its own: you declare yours. The agent reads the sign-in types from
`grant_types_supported` in your OAuth metadata:

| | What the user does | Who sees the credentials | Default |
| --- | --- | --- | --- |
| **Direct** (preferred — [Poppy §4.2](https://personalagentprotocol.org/docs/1.0/spec#direct-sign-in)) | The agent opens your login page (OAuth code + PKCE, optionally pushed first with PAR); the user signs in there as usual and approves the scopes. | Only your app. | on |
| **Device** ([Poppy §4.3](https://personalagentprotocol.org/docs/1.0/spec#device-sign-in)) | The agent shows a short code and a link; the user opens the link on any device, signs in and approves. For agents with no browser (voice, chat). | Only your app. | on |
| **Mediated** ([extension](https://personalagentprotocol.org/docs/1.0/extensions/mediated-sign-in)) | An OAuth extension grant. The agent asks for what your app declares (an email, say), your app sends a one-time code to the user, and the user tells the code to the agent. | The agent relays what the user types — so ask for an identifier and a one-time code, never a password. | off |

Direct and Device need nothing beyond your normal login: AuthKit's pages do it. The consent page
always lists every scope the agent asked for, and marks the ones the account already granted to that
agent ("Already allowed before"). Opening a link never approves anything. Mediated is **transitional**: the protocol plans to retire it on
March 17, 2027, so offer it only until Direct or Device cover the same scopes. It needs a `verify` that checks what the agent sends — or the ready-made
[`poppyEmailCodeSignIn()`](#ready-made-mediated-sign-in-email--code), which does it with your
accounts and email.

## Enabling it

Install the package next to `@adonis-agora/authkit-server`:

```sh
node ace add @adonis-agora/authkit-poppy
```

It has no provider and no env vars of its own: add `poppy()` to `personalAgents.extensions` in
`config/authkit.ts`.

```ts title="config/authkit.ts"
import { poppy } from '@adonis-agora/authkit-poppy'

defineConfig({
  // ...
  personalAgents: {
    // PACT stays optional: omit `audience` for a Poppy-only app.
    extensions: [
      poppy({
        organization: { name: 'Acme', domain: 'acme.com', aliases: ['acme.co.uk'] },
        // `auth.scopes`. Default: `personalAgents.delegation.scopes`.
        scopes: {
          'orders:read': 'See your orders',
          'orders:write': 'Exchange or return items',
        },
        // Optional `auth.scope_hints`: the most consequential action each scope allows.
        scopeHints: {
          'orders:read': { changes: 'none', personal_data: true },
          'orders:write': { changes: 'irreversible', personal_data: true },
        },
        signIn: {
          direct: true, // OAuth code + PKCE on your own page (default on)
          device: { scopes: ['orders:read'] }, // RFC 8628 (default on)
          mediated: {
            // Off unless you configure it: you verify the credentials.
            fields: [
              { name: 'email', label: 'Email', secret: false },
              { name: 'password', label: 'Password', secret: true },
            ],
            scopes: ['orders:read'],
            async verify({ credentials }) {
              const account = await accounts.verifyCredentials(credentials.email, credentials.password)
              if (!account) return { status: 'failed' }
              if (looksUnusual(account)) {
                const code = await sendSmsCode(account) // you send it
                return { status: 'code_required', accountId: account.id, sentTo: 'Text to …71', code }
              }
              return { status: 'complete', accountId: account.id }
            },
          },
        },
        // Your company agent. Omit it and @adonis-agora/agent registers its endpoint (see below).
        agent: {
          protocols: [
            {
              type: 'poppy',
              endpoint: 'https://acme.com/poppy/conversations',
              description: 'Anything about your orders, returns and account',
            },
          ],
        },
        apis: [
          { type: 'openapi', url: 'https://api.acme.com/openapi.json', description: 'Orders, returns' },
          { type: 'mcp', url: 'https://acme.com/mcp', description: 'Product search' },
        ],
        // Optional: task coverage (§9), served at /poppy/tasks.
        tasks: {
          excludedTasks: [
            {
              task: 'Close an account',
              alternative: { references: [{ type: 'web', url: 'https://acme.com/account/close' }] },
            },
          ],
          feedback: { endpoint: 'https://acme.com/poppy/feedback' },
        },
      }),
    ],
  },
})
```

| Field | Default | Notes |
| --- | --- | --- |
| `organization` | — | `name` + `domain` (host only). `poppy.json` and the protected resource metadata are served only on these exact hosts; `www.{domain}` redirects to the domain. Every domain goes to `protected_resources`. On the issuer's host, `organization.domain` carries the issuer's port when it isn't 443 (handy for local testing). |
| `prefix` | `/poppy` | Route prefix and issuer path (`https://acme.com/poppy`). Can't sit under the OIDC `mountPath` or the PACT prefix. |
| `scopes` / `scopeHints` | PACT scopes / — | `auth.scopes` and `auth.scope_hints`. Required unless Direct and Device are both off. |
| `signIn.direct` / `.device` | on, all scopes | `false` disables; `{ scopes }` restricts what that grant can give. With every sign-in type off, `poppy.json` says `auth.disabled: true`. |
| `signIn.mediated` | off | `fields` (reserved OAuth names are refused), `scopes` (required), `verify`, optional `verifyCode`, `codeTtl` (600 s), `maxCodeAttempts` (5). |
| `signIn.limitToResource` | `false` | A sign-in whose first request names `resource` only covers those resources: tokens come out only for them, and the default token only if it named `https://{organization.domain}`. A sign-in without `resource` still covers everything. Off, `resource` in the first request is ignored. |
| `agent` | — | `protocols`: `{ type, endpoint, description }`. `description` (required) says what the agent there can help with. An entry can set `access: 'signed_in'` (needs a sign-in type). |
| `apis` | — | `{ type, url, description }`. |
| `resource` (on `agent`/`apis` entries) | — | The entry only accepts tokens issued for it (RFC 8707). It isn't published: serve that service's protected resource metadata (RFC 9728) yourself. |
| `extensions` | — | Published as is, a list with one entry per version: `{ 'example.com/gift-wrap': [{ version: '1', … }] }`. |
| `tasks` | — | [Task coverage](#task-coverage): `excludedTasks`, `skillIndex`, `feedback`, `resolve`, or `endpoint` for one you serve yourself. |
| `versions` / `preferredVersion` | `{ '1.0': {} }` / newest | [Several protocol versions](#serving-several-versions). |
| `operations` | off | The [Operations extension](#operations) (version 3). `true`, or `{ website, decide, expiresIn }`. |
| `browserControl` | `false` | Lists the [Browser Control extension](#browser-control). Needs browser join. |
| `links` / `disclosures` | `false` | Lists the Links and Disclosures extensions (message content, sent by `@adonis-agora/agent`). |
| `web` | browser join on | `false` publishes no `web`. `disabled: true` asks agents not to browse (no browser join; list `agent` or `apis`). `unscoped` (default `true`) — see [web browsing](#web-browsing). `login(ctx, { accountId, … })` replaces the default login; `redirectTo` (default `/`) is where the browser lands after joining. |
| `par` | offered | Pushed Authorization Requests for Direct Sign-In. `{ required: true }` requires them; `false` doesn't offer them. |
| `clients` | open | `requireRegistration`, `registered`, `blocked` (lists or functions). A refused agent gets `invalid_client` at the authorization server and `invalid_session` at a resource. The [admin console](/docs/admin-console#personal-agents) can allow and block on top of these without a deploy. |
| `allowInsecureClientIds` | `false` | **Development/test only, not spec-compliant.** Accepts `http://` `client_id`s (and their `jwks_uri`/`redirect_uris`) and fetches them without the SSRF guard, so a local agent (the `poppy-agent` CLI of `@adonis-agora/agent`, with `--insecure-dev`, at `http://localhost:7777/agent.json`) can work. Boot fails with `NODE_ENV=production`. |
| `accessTokenTtl` / `refreshTokenTtl` / `sessionTtl` | 1 h / 30 d / 30 d | Access token lifetime, refresh token lifetime, idle Session lifetime. |
| `sessionJwt.maxAge` | 60 s | Acceptance window for a Session JWT's `iat`. |
| `sessionJwt.oneUserPerKey` | `true` | A delegated key that already signed for another User ID gets `invalid_session` while its delegation lasts, so a leaked key exposes one user. `false` turns it off. |
| `dpop` | optional, ES256, 60 s | Binding tokens is your choice: a token request with a proof gets a DPoP-bound token, one without gets Bearer. `required` refuses requests without a proof. A sign-in made with a proof binds its refresh token to that key: a refresh needs a proof from it (`bindRefreshTokens: false` turns this off). Also `requireNonce`, `maxAge`, `algorithms`. |
| `assertionMaxLifetime` | 300 s | Longest client assertion accepted. Can't be lower than 300. |
| `replay` | `'database'` | Where seen `jti`s live: `'database'`, `'memory'`, `{ redis: 'main' }`, or your own `{ claim }`. Session JWTs are claimed too, so every verified request writes one entry. |
| `rateLimit` | 120 sessions/min per agent, 10 mediated attempts/h per identifier | In-memory per process; `false` or your own limiter. Over the limit: HTTP 429 with `Retry-After`. |
| `toActor` | — | Maps a verified principal to your actor (returned as `principal.actor`). |
| `devTools` | offered when the app serves Agora dev tools | Offers the `agora:dev` scope ([below](#developer-tools-over-mcp)). `false` never offers it; `true` always does. |

Lib-owned tables back it — `auth_poppy_sessions`, `auth_poppy_tokens`, `auth_poppy_requests`,
`auth_poppy_grant_keys`, `auth_poppy_grant_resources`, `auth_poppy_delegated_keys`,
`auth_poppy_feedback`, `auth_poppy_operations`, `auth_poppy_operation_revisions`, `auth_poppy_jtis` —
created at boot with AuthKit's own tables
(`schema.autoManage`). If you manage the schema in migrations, call `ensurePoppySchema()` next to
`ensureAuthkitSchema()`:

```ts title="database/migrations/xxxx_authkit_schema.ts"
import { BaseSchema } from '@adonisjs/lucid/schema'
import { ensureAuthkitSchema } from '@adonis-agora/authkit-server'
import { ensurePoppySchema } from '@adonis-agora/authkit-poppy'

export default class extends BaseSchema {
  async up() {
    await ensureAuthkitSchema(this.db)
    await ensurePoppySchema(this.db)
  }
}
```

With [`schema.name`](/docs/settings#database-schema) set, pass the same schema to both:
`{ schema: 'auth' }`.

Refresh tokens are
grants in `auth_agent_grants` (ids `pgrant_…`), so they show up — and are revoked — in the same
**Personal agents** list of the account console as PACT delegations.

## Theming the consent screens

The Direct and Device approval screens (and PACT's delegation screen) render through your
`config.render` as the views **`agents/consent`** and **`agents/done`** — the same mechanism as the
login pages. With `inertiaRenderer`, add them to `views` and write
`inertia/pages/authkit/agents/consent.tsx` / `done.tsx`:

```ts
render: inertiaRenderer({ prefix: 'authkit', views: ['login', 'agents/consent', 'agents/done'] })
```

| View | Props |
| --- | --- |
| `agents/consent` | `csrfToken`, `action` (POST/GET target), `account: { email } \| null`, `error` (`'agents.consent.impersonating'` \| `'agents.consent.invalid_code'` \| `null`), `request: null \| { agentName, agentOrigin, logoUri?, scopes: { id, description }[], hidden?: { name, value }[] (Direct: post them back), userCode? (Device/PACT: post it back as `user_code`) }` |
| `agents/done` | `status: 'approved' \| 'denied' \| 'invalid' \| 'expired'`, `agentName`, `scopes` |

Submit a plain HTML form (`decision=allow|deny`, one `scope` per checked box, `_csrf`): the
controller answers with a redirect to the agent or the `agents/done` view. Without `request`, the
view asks for the device code (a `GET` form with `user_code`). The screens deny framing and refuse an
impersonated session whatever the view looks like.

## Ready-made Mediated Sign-In: email + code

You don't have to write `verify` to offer Mediated Sign-In. `poppyEmailCodeSignIn()` asks the agent
for the account's email, emails a 6-digit code to it and lets the agent submit the code. It uses
AuthKit's own accounts (`accountStore.findByEmail`) and email (AuthKit's default mailer with your
branding and i18n, or your own `sendCode`; without `@adonisjs/mail` the code is logged, for dev):

```ts
import { poppy, poppyEmailCodeSignIn } from '@adonis-agora/authkit-poppy'

personalAgents: {
  extensions: [
    poppy({
      // …
      signIn: {
        mediated: poppyEmailCodeSignIn({
          scopes: ['orders:read'],
          eligible: (account) => account.kind === 'customer', // default: every active account
        }),
      },
    }),
  ],
}
```

| Option | Default | |
| --- | --- | --- |
| `scopes` | required | Scopes this sign-in can grant. |
| `codeTtl` | `600` | Code lifetime, in seconds. |
| `maxCodeAttempts` | `5` | Wrong codes before `invalid_grant`. |
| `eligible` | every active account | `(account) => boolean` — who may sign in this way. |
| `maxPerHour` | `5` | Codes per email per hour, per instance, so an agent can't flood someone's inbox. |
| `label` / `sentTo` | `'Email address'` / `` `Email to a***@example.com` `` | Text the agent shows the person. |
| `sendCode` | AuthKit's mailer | `({ email, code, agentName, expiresInMinutes }) => Promise<void>` — send the code yourself. The default email's texts are the `mail.poppy_sign_in.*` keys, which `i18n.messages` can override. |

It never enumerates accounts: an unknown email, a disabled account, one `eligible` refuses, or an
email over `maxPerHour` all get the same `code_required` answer without a code, and the email is
sent without being awaited so the response time doesn't tell either. The email names the agent
(from its metadata) and tells the person to ignore it if they didn't ask.

## Mediated Sign-In without account enumeration

If you write your own Mediated Sign-In and it only asks for an identifier (email, phone) and then sends a code, answering
`failed` for an unknown identifier tells any agent who has an account. Answer an unknown (or
ineligible) identifier exactly like a real one instead:

```ts
async verify({ credentials }) {
  const account = await accounts.findByEmail(credentials.email)
  const sentTo = `Email to ${mask(credentials.email)}`
  if (!account) return { status: 'code_required', accountId: null, sentTo } // no code is sent
  const code = randomCode()
  await mail.sendLater(/* … code … */) // queue it: the same work, and time, on both paths
  return { status: 'code_required', accountId: account.id, sentTo, code }
}
```

With `accountId: null` AuthKit answers the same `code_required` error, and every code submitted for
that sign-in is treated as a wrong code — same attempt counting, same `invalid_grant` at the end.
Rate limits (`rateLimit.mediatedPerHour`, the OTP throttle) still apply.

CSRF, deny framing, refuse impersonation and never approve on open.

## Protecting your APIs

```ts title="start/routes.ts"
import { poppyAuth, poppyOf } from '@adonis-agora/authkit-poppy'

router
  .post('/orders/:id/exchanges', async (ctx) => {
    const p = poppyOf(ctx)! // { userId, agentId, accountId, clientId, scopes, sessionId, signedIn, … }
    // …act on p.accountId
  })
  .use(poppyAuth({ scopes: ['orders:write'] }))
```

`poppyAuth()` / `verifyPoppyRequest(ctx | { method, url, headers }, options)` verify the
`Poppy-Session` JWT and its delegation (`poppy_dlg`, `poppy-delegation+jwt`, `ES256` or `PS384`, at
most 24 hours): `typ`, `aud` (your issuer), `htm`, `htu`, the `iat` window, `ath`, the `jti`. They
check `Poppy-Version` (compatible with a version you serve: any `1.x` by default), and read
`Poppy-Extensions`. A new `client_id` + `sid` + User ID starts a signed-out Session; a known one
continues it, and must keep the `Poppy-Version` it started with. If the request has an access token, they also
check it was issued to the same `client_id`, its DPoP proof when bound, its `resource`, whether its
refresh token is still alive, and its scopes.

Options: `scopes` (all required), `signedIn` (needs an access token), `resource`, and `extension` —
a name the request must declare in `Poppy-Extensions`, in a version you list in `extensions`.

The principal has `protocolVersion` (the request's `Poppy-Version`), `documentVersion` (the served
version the request is handled under) and `extensions` (`name → version`, only the ones you list), so
a route can answer with what that version defines. `poppyAuth()` adds `Deprecation`/`Sunset` to the
response when that version is being retired; with `verifyPoppyRequest()`, send `result.headers`.

| Failure | Status | Where |
| --- | --- | --- |
| `invalid_session` | 400 | JSON body. A Session check failed, the agent was refused, or the delegated key already signed for another User ID. |
| `session_ended` | 400 | JSON body. The Session ended, it already used a different account, or the request changed `Poppy-Version` mid-Session. The agent starts a new Session. |
| `version_unsupported` | 400 | JSON body. `Poppy-Version` is missing or no served version is compatible with it. |
| `extension_required` | 403 | JSON body, with `extension`. The route's `extension` isn't declared. |
| No error code | 401 | `WWW-Authenticate` with the `scope` needed: the request needs the account and has no access token. |
| `invalid_token` | 401 | `WWW-Authenticate`. Expired, revoked or not issued for this resource. |
| `insufficient_scope` | 403 | `WWW-Authenticate`, with `scope`. |
| `invalid_dpop_proof` / `use_dpop_nonce` | 401 | `WWW-Authenticate`, with `DPoP-Nonce`. |
| Rate limit | 429 | `Retry-After`, no body. |

Tokens are never read from the URL. These helpers always verify the Session; a route that uses no
Session claims can validate its OAuth token some other way, as the spec allows.

`verifyDpopProof()` is exported on its own for other resource servers.

## MCP

A Poppy agent asks for a token with `resource` set to an MCP URL — one of your `apis` of type `mcp`,
or one registered in the `@adonis-agora/oauth:resources` slot (what `@adonis-agora/agent`'s MCP
provider does). It's always a Bearer token, even if the request has a DPoP proof, since these servers
don't advertise DPoP. It is minted as an oidc-provider access token (`aud` = the MCP URL, scopes = the
granted scopes), so the existing `authKitAuth()` MCP integration accepts it with no extra code, and a
sign-out revokes it. It works only at that server. MCP clients that don't implement Poppy sign in with
MCP's own flow, and their requests belong to no Session.

## Developer tools over MCP

When the app serves `@adonis-agora/agent`'s developer tools (`/mcp/agora`), Poppy also offers the
`agora:dev` scope. A personal agent that holds it may call those tools, within what each tool's
own access rules allow.

- On the consent screen `agora:dev` is **not ticked**: the person must tick it to grant it.
  Unticked, the agent gets the other scopes and no dev tools.
- Mediated Sign-In can't grant it (there is no consent screen); listing it in
  `signIn.mediated.scopes` fails at boot.
- A sign-in type with its own `{ scopes }` list only offers it if you add it there.
- Set `devTools: false` to never offer it, or give it your own text in `scopes`:

```ts title="config/authkit.ts"
poppy({
  // ...
  scopes: { 'orders:read': 'See your orders', 'agora:dev': 'Read the shop internals' },
  devTools: false,
})
```

## The company agent (`@adonis-agora/agent`)

Conversations ([Poppy §8](https://personalagentprotocol.org/docs/1.0/spec#conversations)) are implemented by `@adonis-agora/agent`. Neither package imports the other;
they meet through two global slots:

```ts
// authkit → agent: authenticate a request (installed at boot when `poppy()` is in `extensions`)
const authenticate = globalThis[Symbol.for('@adonis-agora/poppy:authenticate')]
const result = await authenticate(
  { method: 'POST', url: 'https://acme.com/poppy/conversations', headers },
  { scopes: ['orders:read'], signedIn: true }, // optional
)
// { ok: true, principal: { userId, agentId, accountId, clientId, scopes, sessionId, signedIn,
//                          resource, tokenType, protocolVersion, extensions, actor? } }
// | { ok: false, status: 400 | 401 | 403 | 429, error, scope?, wwwAuthenticate, body,
//     description, headers }
// Answer `body` as JSON when it isn't null (`invalid_session`, `session_ended`,
// `version_unsupported`, `extension_required`); otherwise send `wwwAuthenticate`.
// `error` is null for the 401 without a code and for the 429.

// agent → authkit: where the conversations live (used when `agent.protocols` is not configured)
globalThis[Symbol.for('@adonis-agora/poppy:endpoints')] = {
  conversations: 'https://acme.com/poppy/conversations',
  description: 'Anything about your orders, returns and account', // required to be published
}
```

With [`operations`](#operations) on, a third slot, `Symbol.for('@adonis-agora/poppy:operations')`,
gives the conversation endpoint the same operations service the app uses (`require`, `get`,
`markPerformed`, `release`). It's absent when the extension is off.

`userId` is the Poppy **User ID** (opaque, per agent user); `sessionId` is unique per `client_id` +
`sid` + User ID; `protocolVersion` is the version the request declared, so the conversation endpoint
sends only what that version defines; `accountId` is the account in your app when signed in. `actor` is whatever your `toActor` returns. `Symbol.for('@adonis-agora/poppy:issuer')`
holds the Poppy issuer (for the MCP protected-resource metadata).

## Web browsing

A browser joins a Session in three steps, so that only the right browser and the right agent can
complete a join, and the access token never reaches the browser:

1. The agent's browser loads `GET /poppy/browser-session`: a form with a one-time code (60 s), and a
   `__Host-poppy_join` cookie (`SameSite=Strict`) that ties the code to that browser.
2. The agent sends the code to `POST /poppy/browser-session/authorize` as `{ "code": "…" }`, with its
   Session header and, if signed in, its access token. `204`, or `400 invalid_request`. An access
   token without `poppy:browser-sign-in` gets `403 insufficient_scope`.
3. The browser submits the form. The first submission uses up the code, whatever the result. On
   success AuthKit regenerates the app session, marks it as the agent's and answers `303` to
   `web.redirectTo`; otherwise an error page with no cookie.

A join **with** an access token logs the browser in to that account with AuthKit's account session
(+ `adonisAuth.guard`), replacing any other login, and an earlier login doesn't come back.

`poppy:browser-sign-in` is added to your scopes (and to Direct and Device) whenever browser join is on
and a sign-in type is offered. The default login gives the browser the **whole account**, so
`web.unscoped` defaults to `true`: `poppy.json` says so, and the scope reads "Browse the website, and
see and do anything your account can do there". If your `web.login` applies the cookie's scopes
(`poppyWebSessionOf(ctx).scopes`) to every website action, set `unscoped: false`; the scope then reads
"Use the website signed in, with the other access you approve". Give it your own text in `scopes` if
you like. A join
**without** one leaves the browser's own login alone. Use `web.login` if your app logs users in some
other way.

Add `poppyWebSession()` to your router middleware so the cookie stops acting for the account when the
sign-in ends (sign-out, disconnection) and doesn't outlive the Session; `poppyWebSessionOf(ctx)` gives
you its scopes. The cookie keeps the account and scopes authorized at step 2: the agent joins again to
change them. An agent's browser is refused by the account console, the admin console and the consent
screens.

## Task coverage

With `tasks`, `poppy.json` lists `tasks.endpoint` (`/poppy/tasks`), and agents fetch it early in each
Session with the Session header:

```ts title="config/authkit.ts"
poppy({
  // ...
  tasks: {
    excludedTasks: [
      { task: 'Send a wire transfer', alternative: { instructions: 'Only in the Acme app.' } },
    ],
    skillIndex: {
      $schema: 'https://schemas.agentskills.io/discovery/0.2.0/schema.json',
      skills: [
        {
          name: 'manage-bookings',
          description: "Manage the user's bookings",
          type: 'skill-md',
          url: 'https://cdn.acme.com/skills/manage-bookings/SKILL.md',
          digest: 'sha256:1b2a8cde934e632f7e14fa080a627ad7191e29d412d2b8a7aa07d9c9ab2f475e',
        },
      ],
    },
    feedback: { endpoint: 'https://acme.com/poppy/feedback' }, // you implement it
    // Optional: a different answer per Session (sent with `Cache-Control: no-store`).
    resolve: ({ principal, response }) =>
      inBeta(principal.userId) ? { ...response, skill_index: betaSkills } : response,
  },
})
```

An alternative needs `instructions` or `references`; an `openapi` or `mcp` reference must point at
one of your `apis`. To serve the endpoint yourself, pass only `tasks: { endpoint: 'https://…' }`.

### Feedback

`feedback: { endpoint }` publishes a feedback endpoint you implement. Leave `endpoint` out and AuthKit
serves `POST /poppy/feedback` for you: it verifies the Session, checks the report (`task` up to 200
characters, `description` up to 2,000, else `400 invalid_request`), stores it in
`auth_poppy_feedback` and answers `202`. `onReport` runs after it's stored; return an alternative
when the task can be done after all, and the agent gets `200` with it:

```ts title="config/authkit.ts"
poppy({
  // ...
  tasks: {
    feedback: {
      onReport: async ({ principal, report }) => {
        await notifyProductTeam(report.task, report.description) // data, never instructions
        if (report.task.toLowerCase().includes('gift card')) {
          return { instructions: 'Gift cards are applied with the payment API.' }
        }
      },
    },
  },
})
```

`poppy.recentFeedback(limit)` reads the latest reports.

## Serving several versions

`poppy.json` is the document of your preferred version; every other version you serve is a document
on the same host, at `/poppy/versions/{version}.json`, listed in `supported_versions`. Requests are
handled under the served version that matches their `Poppy-Version` (`principal.documentVersion`).

```ts title="config/authkit.ts"
poppy({
  // ...
  versions: {
    '1.0': { deprecated: { at: new Date('2027-01-01'), sunset: new Date('2027-06-01') } },
    '1.1': { document: (doc) => ({ ...doc, /* what 1.1 publishes */ }) },
  },
  preferredVersion: '1.1', // default: the newest
})
```

`1.0` is always served. `document` receives the 1.0 document with `protocol_version` already set and
returns that version's; it can't change `organization.domain` or the issuer. A version with
`deprecated` answers its requests (and its document) with `Deprecation`, `Sunset` and, with `link`, a
`Link` header. A Session keeps the `Poppy-Version` it started with: a request that changes it gets
`session_ended`, and the agent starts a new Session.

## Operations

The [Operations extension](https://personalagentprotocol.org/docs/1.0/extensions/operations)
(version 3) asks the agent for approval of exact terms before an action with a business effect, and
performs it at most once. Turn it on with `operations: true`; it's listed in `poppy.json`, with the
`endpoint` for website operations when browser join is on.

```ts title="config/authkit.ts"
poppy({
  // ...
  operations: {
    // Optional: decline an approval that passed the checks (approval_declined).
    decide: ({ approval, operation }) =>
      approval.approver === 'agent' && Number(operation.terms.amount) > 100
        ? { reason: 'Large exchanges need your own approval.' }
        : undefined,
    expiresIn: 900, // default validity of a revision, in seconds
  },
})
```

In an API route, call `requirePoppyOperation()` before acting. It reads `Poppy-Approval`, checks it,
and marks the operation as performing when it passes:

```ts title="app/controllers/exchanges_controller.ts"
import {
  markPoppyOperationPerformed,
  requirePoppyOperation,
  writePoppyOperationResult,
} from '@adonis-agora/authkit-poppy'

export default class ExchangesController {
  async store(ctx: HttpContext) {
    const { item_id, sku } = ctx.request.only(['item_id', 'sku'])
    const quote = await exchanges.quote(ctx.params.id, item_id, sku) // today's price
    const result = await requirePoppyOperation(ctx, {
      interface: 'api',
      action: { method: 'POST', url: ctx.request.url(), item_id, sku }, // what the request asks
      terms: { order_id: ctx.params.id, item_id, sku, price_difference: quote.difference },
      summary: `Exchange for **${sku}**, ${quote.difference.amount} ${quote.difference.currency} more.`,
      idPrefix: 'exc_',
    })
    if (!result.ok) return writePoppyOperationResult(ctx, result)

    const exchange = await exchanges.perform(ctx.params.id, item_id, sku, {
      idempotencyKey: result.operationId, // a retry can't perform it twice downstream either
    })
    await markPoppyOperationPerformed(result.operationId, { status: 201, body: exchange })
    return ctx.response.status(201).json(exchange)
  }
}
```

The route needs `poppyAuth()`. What you get back:

| `kind` | Status | Meaning |
| --- | --- | --- |
| `approved` (`ok: true`) | — | Perform the action, then `markPoppyOperationPerformed(id, response)`. If it failed without effect, `releasePoppyOperation(id)` lets the same approval retry. |
| `approval_required` | 403 | Nothing done; the body carries the operation (`operation_id`, `revision`, `terms`, `summary`, `expires_at`). Terms or the request changed since the approval: same `operation_id`, new `revision`. |
| `approval_declined` | 403 | Your `decide` declined it; nothing recorded. |
| `performed` | as first time | Already performed: the response you stored, repeated. |
| `performing` | 503 | Still running (`Retry-After`). |
| `challenge` | 401 | The operation belongs to an account and the request is signed out. |
| `extension_required` | 403 | The request didn't declare `operations` version 3. Handle approval yourself, or send it. |
| `invalid_request` | 400 | A malformed `Poppy-Approval`. |

An operation can be approved by the same agent and User in any Session — signed in to the same
account if it was returned signed in, signed out otherwise. Revisions, approvals (`approver`,
`approved_at`, `input_type`, `reference`) and the stored response live in `auth_poppy_operations`
and `auth_poppy_operation_revisions` until the revision expires.

**MCP**: pass the tool arguments as `action` and the approval from
`params._meta['personalagentprotocol.org/approval']` (`approvalFromMcpMeta(meta)`) as `approval`, with
the principal; `poppyOperationToolResult(result)` turns a refusal into the tool error result.
**Conversations** (`@adonis-agora/agent`) pass the message's `extensions.operations.approval` and use
the conversation as `action`; `operationId` gives an operation a new revision when the user asks for
other terms.

**Websites**: in a browser joined to a Session that declared the extension, call
`requirePoppyOperation(ctx, { interface: 'website', action, terms, summary })` from the page's
handler (with `poppyWebSession()` in the router middleware). It performs nothing and answers `403`
with `Poppy-Operation: sid="…", ref="…"` — a waiting page, or `{ "error": "approval_required" }` for a
script that accepts JSON. The agent gets and approves the operation at `POST /poppy/operations`; when
the browser repeats the request, the oldest matching recorded approval is used, once. Make the page's
action repeatable (a **Continue** button), and let your CDN pass a `403` with `Poppy-Operation`
through. A browser with its own login (joined without an access token) gets `kind: 'unsupported'`:
handle approval on your site as usual.

## Browser Control

With `browserControl: true`, `poppy.json` lists the Browser Control extension (version 1): mark the
steps the user should take themselves, and an agent that declared it leaves them to the user.

```edge title="resources/views/check_in.edge"
<form method="post" action="/bookings/{{ booking.id }}/check-in" {{{ poppyUserStep('submission') }}}>
  <input type="hidden" name="controller">
  <button type="submit">Check in</button>
</form>
<script>
  document.forms[0].elements.controller.value = navigator.poppy?.controller ?? ''
</script>
```

`poppyUserStep(step)` is an Edge global (registered at boot when edge.js is installed) and a function;
`poppyUserStepAttrs(step)` gives `{ 'data-poppy-user-step': step }` for JSX. `interaction` on a
control or form leaves it to the user; `submission` on a form lets the agent fill it in but not submit
it. `poppyBrowserControlOf(ctx)` says whether this browser declared the extension, and
`poppyControllerOf(value)` reads the `controller` the page sent (`'user'`, `'agent'` or `null`). It
isn't signed: record it, but your server still checks every action.

## Signing out and disconnecting

The agent revokes its refresh token at `/poppy/oauth/revoke`: its access tokens die with it, and its
Sessions continue signed out. The user can disconnect the agent from **Account → Apps → Personal
agents** (or `DELETE /account/api/agents/:id`), and "sign out everywhere", password resets, account
deletion and admin actions revoke every refresh token too. Admins can revoke any connection, or block
an agent outright, from the [admin console](/docs/admin-console#personal-agents).

## Spec notes

Where the spec leaves a choice, AuthKit makes these:

- A Session that used one account refuses another with `session_ended` (§5.4 allows it).
- Sessions that ended (an agent blocked in the admin console) or went idle for `sessionTtl` answer
  `session_ended`.
- Reused `jti`s are refused for client assertions and Session JWTs (§4.1 and §5.3 allow it).
- `jwks_uri` and `redirect_uris` must be on the **same host** as `client_id`, except loopback redirect
  URIs, which only match the `127.0.0.1` and `[::1]` literals, with any port.
- AuthKit always runs an issuer, so its Companies are never issuerless: Session JWTs use the issuer
  as `aud`, even when both sign-in types are off.
- Revoking another agent's refresh token is a silent no-op (RFC 7009).

- The consent page marks scopes the account already granted to the agent (§10.8 allows it).
- A delegated key that signed for one User ID can't sign for another while its delegation lasts
  (§5.2 allows it; `sessionJwt.oneUserPerKey`).
- A Session that changes `Poppy-Version` gets `session_ended`, as an account change does.

Operator signatures (Web Bot Auth) are your edge's concern, and PS384 delegations are accepted for
blind signing. Links and Disclosures are message content: `@adonis-agora/agent` sends them.

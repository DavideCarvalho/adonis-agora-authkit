Every `@adonis-agora/authkit-*` package moves to **1.0.0**. Most apps upgrade by bumping the
versions; the changes below only affect apps that use one of the APIs listed.

## Requirements

- **Node.js 24 or newer.** Every package declares `"engines": { "node": ">=24" }` and is tested
  on Node 24 and 26.
- The `@adonis-agora/*` peers (`durable`, `media`, `telescope`, `resilience`,
  `authkit-server`) accept both their 0.x and 1.x lines, so you can upgrade them in any order.

```sh
pnpm add @adonis-agora/authkit-server@^1.0.0 @adonis-agora/authkit-client@^1.0.0
```

## Drop `withMfa()` from your model

`lucidAccountStore` keeps the MFA state (TOTP secret, recovery codes) in its own `auth_mfa`
table, so the model needs no MFA mixin. `withMfa` is no longer exported: remove it from the
import and from `compose(...)`. Nothing else changes and no migration is needed.

Before:

```ts title="app/models/auth_user.ts"
import { compose } from '@adonisjs/core/helpers'
import { BaseModel } from '@adonisjs/lucid/orm'
import { withAuthUser, withCredentials, withMfa } from '@adonis-agora/authkit-server'

export default class AuthUser extends compose(
  BaseModel,
  withAuthUser(),
  withCredentials(),
  withMfa()
) {}
```

After:

```ts title="app/models/auth_user.ts"
import { compose } from '@adonisjs/core/helpers'
import { BaseModel } from '@adonisjs/lucid/orm'
import { withAuthUser, withCredentials } from '@adonis-agora/authkit-server'

export default class AuthUser extends compose(BaseModel, withAuthUser(), withCredentials()) {}
```

## Grant sudo with `completeSudo`

`markSudo` is no longer exported. To grant sudo from your own handler (for example the
callback of an `oidcStepUp()` confirmation), build the context with `sudoContextFrom` and call
`completeSudo`. It stamps the grace window, writes the `sudo.confirmed` audit event, remembers
the method and redirects to the validated `return_to`.

Before:

```ts title="app/controllers/step_up_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'
import { markSudo } from '@adonis-agora/authkit-server'

export default class StepUpController {
  async callback(ctx: HttpContext) {
    // … validate the step-up grant
    markSudo(ctx)
    return ctx.response.redirect('/account/security')
  }
}
```

After:

```ts title="app/controllers/step_up_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'
import { completeSudo, failSudo, sudoContextFrom } from '@adonis-agora/authkit-server'

export default class StepUpController {
  async callback(ctx: HttpContext) {
    const c = await sudoContextFrom(ctx)
    const grant = await exchangeAndValidate(ctx)
    if (!grant) return failSudo(c, 'account.confirm.error')

    return completeSudo(c, 'oidc-step-up')
  }
}
```

To check whether the current request already holds sudo, keep using `isSudoActive` or
`requireSudo`. See [Console session & sudo mode](/docs/console-session).

## Send email-change confirmations with `onEmailChangeConfirm`

When a user changes their email address, the confirmation link goes through
`mail.onEmailChangeConfirm`. If that hook is not set, AuthKit sends its built-in confirmation
email. `onEmailVerification` is only used for verifying the address at signup and no longer
receives email-change confirmations.

If you relied on `onEmailVerification` for both, add `onEmailChangeConfirm`.

Before:

```ts title="config/authkit.ts"
import mail from '@adonisjs/mail/services/main'

defineConfig({
  // …
  mail: {
    // Also received the email-change confirmation link.
    onEmailVerification: async ({ email, verifyUrl }) => {
      await mail.send((m) => m.to(email).subject('Confirm your email').text(verifyUrl))
    },
  },
})
```

After:

```ts title="config/authkit.ts"
import mail from '@adonisjs/mail/services/main'

defineConfig({
  // …
  mail: {
    onEmailVerification: async ({ email, verifyUrl }) => {
      await mail.send((m) => m.to(email).subject('Confirm your email').text(verifyUrl))
    },
    onEmailChangeConfirm: async ({ email, confirmUrl }) => {
      await mail.send((m) => m.to(email).subject('Confirm your new email').text(confirmUrl))
    },
  },
})
```

See [Compliance](/docs/compliance) for the full email-change flow.

## List your React pages in `inertiaRenderer({ views })`

`views` is required. Screens listed there render through Inertia; every other screen uses the
built-in Edge view. List the pages you have under `inertia/pages/<prefix>/`.

Before:

```ts title="config/authkit.ts"
defineConfig({
  // …
  render: inertiaRenderer({ prefix: 'authkit' }),
})
```

After:

```ts title="config/authkit.ts"
defineConfig({
  // …
  render: inertiaRenderer({
    prefix: 'authkit',
    views: ['login', 'consent', 'signup', 'forgot', 'reset', 'verify-email', 'mfa-challenge'],
  }),
})
```

## Send `grantTypes` to the Admin API

`POST` and `PATCH` on `/api/authkit/v1/clients` (and the admin console form) read the grants from `grantTypes` only.
A `grants` field in the request body is ignored. Responses keep returning `grants`.

Before:

```json
{ "redirectUris": ["https://app.acme.com/auth/callback"], "grants": ["authorization_code", "refresh_token"] }
```

After:

```json
{ "redirectUris": ["https://app.acme.com/auth/callback"], "grantTypes": ["authorization_code", "refresh_token"] }
```


## Create OIDC clients outside `defineConfig`

`defineConfig` no longer takes a `clients` list. Clients live in the adapter: create them in the
admin console, through the Admin API (`POST /api/authkit/v1/clients`), or with
`node ace authkit:clients:create`. The command's `--client-secret` keeps the secret your relying
parties already use.

Before:

```ts title="config/authkit.ts"
defineConfig({
  // …
  clients: [
    {
      clientId: 'web',
      clientSecret: env.get('WEB_CLIENT_SECRET'),
      redirectUris: ['https://app.acme.com/auth/callback'],
      postLogoutRedirectUris: ['https://app.acme.com/'],
      grants: ['authorization_code', 'refresh_token'],
      backchannelLogoutUri: 'https://app.acme.com/auth/backchannel-logout',
    },
    { clientId: 'mobile', applicationType: 'native', redirectUris: ['com.acme.app:/oauth'] },
  ],
})
```

After, once per environment:

```sh
node ace authkit:clients:create \
  --client-id=web \
  --client-secret="$WEB_CLIENT_SECRET" \
  --redirect-uri=https://app.acme.com/auth/callback \
  --post-logout-uri=https://app.acme.com/ \
  --grant=authorization_code --grant=refresh_token \
  --backchannel-logout-uri=https://app.acme.com/auth/backchannel-logout

node ace authkit:clients:create --client-id=mobile --native --redirect-uri=com.acme.app:/oauth
```

`backchannelLogoutSessionRequired` has no CLI flag: set it in the admin console or with
`PATCH /api/authkit/v1/clients/:id` after creating the client.

## Use `authkit_context_middleware` and `ctx.authkit`

`authkit_middleware` is removed. Register `authkit_context_middleware`, which puts AuthKit's
authenticator on `ctx.authkit`. `ctx.auth` belongs to `@adonisjs/auth`: if you want
`ctx.auth.user` and `middleware.auth()`, add [`authkitClientGuard`](/docs/adonis-auth).

Before:

```ts title="start/kernel.ts"
router.use([
  () => import('@adonisjs/session/session_middleware'),
  () => import('@adonis-agora/authkit-client/authkit_middleware'),
  () => import('@adonis-agora/authkit-client/backchannel_revocation_middleware'),
])
```

```ts title="app/controllers/dashboard_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'

export default class DashboardController {
  async show({ auth, inertia }: HttpContext) {
    const user = await auth.getUser()
    return inertia.render('dashboard', { user, isAdmin: auth.hasGlobalRole('ADMIN') })
  }
}
```

After:

```ts title="start/kernel.ts"
router.use([
  () => import('@adonisjs/session/session_middleware'),
  () => import('@adonis-agora/authkit-client/authkit_context_middleware'),
  () => import('@adonis-agora/authkit-client/backchannel_revocation_middleware'),
])
```

```ts title="app/controllers/dashboard_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'

export default class DashboardController {
  async show({ authkit, inertia }: HttpContext) {
    const user = await authkit.getUser()
    return inertia.render('dashboard', { user, isAdmin: authkit.hasGlobalRole('ADMIN') })
  }
}
```

Type `getUser()` once instead of augmenting `HttpContext.auth`:

```ts title="types/authkit.ts"
import type AppUser from '#models/app_user'

declare module '@adonis-agora/authkit-client' {
  interface AuthkitUserType {
    user: AppUser
  }
}
```

The Inertia shared prop for `@adonis-agora/authkit-react` reads `ctx.authkit.toSharedProps()`.

## Load account data with the query options

`useProfile`, `useSessions`, `useAuthorizedApps`, `useOrganizations`, `useOrganization`,
`useOrgInvitations` and `useSwitchOrganization` are removed, along with the `profile`,
`sessions`, `apps`, `orgs` and `orgInvitations` keys of `AuthkitProvider`'s `endpoints`. Use the
TanStack Query options, which read the Account API (`/account/api/*`). The `/account/orgs/json`,
`/account/orgs/invitations/json` and `/account/orgs/:id/json` routes are gone too.

Before:

```tsx title="inertia/pages/account/profile.tsx"
import { useProfile, useSessions } from '@adonis-agora/authkit-react'

export default function Profile() {
  const { data: user, actions } = useProfile()
  const { data: sessions } = useSessions()
  return <ProfileForm user={user} sessions={sessions} onSave={actions.update} />
}
```

After:

```tsx title="inertia/pages/account/profile.tsx"
import { useMutation, useQuery } from '@tanstack/react-query'
import {
  useAccountSessionsQueryOptions,
  useMeQueryOptions,
  useUpdateProfileMutationOptions,
} from '@adonis-agora/authkit-react'

export default function Profile() {
  const { data: me } = useQuery(useMeQueryOptions())
  const { data: sessions } = useQuery(useAccountSessionsQueryOptions())
  const update = useMutation(useUpdateProfileMutationOptions())
  return <ProfileForm user={me} sessions={sessions?.sessions} onSave={update.mutate} />
}
```

| Removed | Use |
| --- | --- |
| `useProfile()` | `useMeQueryOptions()`, `useUpdateProfileMutationOptions()` |
| `useSessions()` | `useAccountSessionsQueryOptions()`, `useRevokeSessionMutationOptions()` |
| `useAuthorizedApps()` | `useAppsQueryOptions()`, `useRevokeAppMutationOptions()` |
| `useOrganizations()` / `useOrganization(id)` / `useOrgInvitations()` | `useAccountOrgsQueryOptions()` and the other `useAccountOrg*` options |
| `useSwitchOrganization()` | `useAccountActivateOrgMutationOptions()`, `useAccountDeactivateOrgMutationOptions()` |

`UserProfile`, `AuthorizedApps`, `OrganizationSwitcher` and `OrganizationProfile` load through
the same options, so wrap your app in `QueryClientProvider` and `AuthkitClientProvider`:

```tsx title="inertia/app/app.tsx"
import { QueryClientProvider } from '@tanstack/react-query'
import {
  AuthkitClientProvider,
  AuthkitProvider,
  createAuthkitQueryClient,
} from '@adonis-agora/authkit-react'

const queryClient = createAuthkitQueryClient()

createInertiaApp({
  // …
  setup({ el, App, props }) {
    createRoot(el).render(
      <QueryClientProvider client={queryClient}>
        <AuthkitClientProvider>
          <AuthkitProvider>
            <App {...props} />
          </AuthkitProvider>
        </AuthkitClientProvider>
      </QueryClientProvider>,
    )
  },
})
```
